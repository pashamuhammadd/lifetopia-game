# Platform integration — future design, not implementation

Existing platform repo: https://github.com/pashamuhammadd/lifetopia-platform ; website lifetopiaworld.io, community domain `community.lifetopiaworld.io`, game `play.lifetopiaworld.io`, docs and grants subdomains. Keep existing shared account and user identity. No new independent identity system for the game.

M0–M4 do not access production Supabase, Solana or community. Do not use connected Supabase MCP for writes. M5 begins with read-only audit of actual auth, user IDs, profile schema, RLS, API routes and web shell; never assume session cookies work across subdomains. Document current deployment, CORS, origin allowlist, session expiry/revocation, secure cookie policy and CSRF. Design a reviewed login handoff using short-lived single-use exchange credentials where appropriate; avoid secrets in URLs, logs or persistent browser storage. JavaScript bridge sends only minimum needed data to Unity; backend validates identity and permissions on every relevant call. No service role or wallet private keys in client, including Web build. Public client keys alone do not authorize data access.

Server owns balances, inventory, rewards, quest claims and transactions. Use idempotency and transactional checks; never promote untrusted local save into online economy. Staging/test accounts only for initial integration; privacy review, rate limits, recovery, deletion and moderation before public social features. Multiplayer dedicated server architecture is TBD; Supabase is not assumed to replace authoritative real-time simulation. Web3 after stable gameplay, optional wallet; devnet first; no token launch or earnings promises.

Future community links: game profile, achievements, shareable house, friends and event status; require explicit privacy controls and player consent for public posts. Maintain separate deployment pipeline for Unity build. Existing live platform remains unchanged until approved rollout.
